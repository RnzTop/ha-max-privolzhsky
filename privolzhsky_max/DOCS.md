# MAX — Техцентр «Приволжский», 1.1.0

Главное меню: **«Записаться на ремонт»** и **«Контакты»**. Услуги, цены и FAQ убраны по запросу владельца. Запись больше не требует открытия сайта.

## Как работает заявка

1. Клиент в личном диалоге нажимает «Записаться на ремонт».
2. Имя автоматически берётся из профиля MAX; вопроса об имени нет. Если имя не пришло, в заявке будет «Имя не указано в профиле».
3. Бот просит только телефон. Номер можно ввести с +7 или 8, с пробелами, скобками и дефисами.
4. Показываются имя и телефон, объяснение передачи сотрудникам в закрытый рабочий чат и кнопки «Передать сотрудникам», «Изменить телефон», «Отмена».
5. Только после подтверждения заявка сохраняется и отправляется сотрудникам в настроенную рабочую группу MAX.
6. После успешного ответа API о приёме сообщения в группу клиент получает сообщение «Заявка передана в рабочий чат». Это не подтверждение прочтения сотрудниками и не подтверждённая запись. Услугу и время сотрудник уточняет при звонке.

До подтверждения данные в рабочую группу не передаются. Отменить незавершённую форму можно кнопкой, `/cancel`, `/start` или возвратом в меню. После нажатия «Передать сотрудникам» отмена формы уже не отзывает отправленную заявку.

## Обновление с первой версии

1. В магазине приложений HA нажмите ⋮ → «Проверить обновления», обновите страницу.
2. Откройте «MAX — Техцентр Приволжский» и обновите до **1.1.0**. Не удаляйте приложение: токен и данные сохранятся. Резервная копия перед обновлением желательна.
3. В конфигурации появятся `staff_chat_id` и `setup_mode`. Остальные настройки оставьте прежними.
4. Настройте рабочую группу по инструкции ниже, сохраните конфигурацию и перезапустите приложение.
5. В личном диалоге отправьте `/start`, чтобы получить актуальное меню из двух кнопок. Сообщения со старым меню из истории MAX автоматически не удаляются.

## Как подключить рабочую группу

Бот не выбирает группу по названию и не начинает отправку в первую попавшуюся группу. Получатель задаётся вручную числовым ID в HA.

1. В кабинете MAX разрешите боту работу в групповых чатах. Подготовьте закрытую рабочую группу только с сотрудниками.
2. В конфигурации приложения включите `setup_mode: true`, поле `staff_chat_id` пока оставьте пустым. Сохраните и перезапустите приложение.
3. Добавьте бота в рабочую группу. В журнале HA должна появиться строка **«Настройка: ID рабочего чата = …»**. Скопируйте номер целиком, включая минус, если он есть. Этот режим выводит только ID группы, без имён сотрудников и сообщений.
4. Если бот уже был добавлен, отправьте в этой группе `/chatid`. При включённом `setup_mode` бот ответит ID именно этой группы. Для получения обычных сообщений группового чата MAX требует права администратора с чтением сообщений (`read_all_messages`); если ответа нет, проверьте права бота. Альтернатива — удалить и заново добавить бота при включённом режиме настройки, чтобы получить событие `bot_added`. Это изменяет членство бота в вашей группе; выполняйте этот шаг самостоятельно при необходимости.
5. Вставьте номер в `staff_chat_id` в HA. Выключите `setup_mode`, сохраните и перезапустите. Пример (это не ID вашей группы):

```yaml
staff_chat_id: "-123456789"
setup_mode: false
```

6. В журнале должны появиться «Рабочая группа доступна боту» и «Бот запущен». При запуске проверяются тип и активное членство в группе. Проверка не отправляет тестовых сообщений и сама по себе не доказывает наличие права на отправку — это проверяется следующим шагом.
7. В личном диалоге с ботом отправьте `/start`, нажмите «Записаться на ремонт», введите свой телефон и подтвердите отправку. В рабочую группу должна прийти заявка с именем из MAX и телефоном. Затем в личный диалог — подтверждение передачи.

Не указывайте ID канала, личного диалога или клиентской группы. Пока `staff_chat_id` пуст, бот не собирает телефон и предлагает позвонить в техцентр. В обычном режиме бот не отвечает на разговоры в группе и не выполняет команду `/chatid`.

## Настройки

| Поле | Назначение |
|---|---|
| `access_token` | Токен бота MAX. Вводите только в HA, не публикуйте |
| `mode` | `polling` для проверки или `webhook` для постоянной работы |
| `staff_chat_id` | Числовой ID закрытой рабочей группы, может быть отрицательным |
| `setup_mode` | Временно включить получение ID группы, затем выключить |
| `webhook_url` | Для webhook: `https://ВАШ-ДОМЕН/max/webhook` |
| `webhook_secret` | Для webhook: случайные 16–256 латинских букв, цифр, `_`, `-` |

Токен не включён в код, журналы и публичный репозиторий. Настройки HA и резервные копии могут содержать токен и персональные данные — храните их с ограниченным доступом.

## Если заявка не пришла

- Пустой `staff_chat_id`: приложение ещё ожидает настройки рабочей группы.
- «Рабочая группа недоступна», HTTP 403/404: проверьте ID, членство и права бота.
- HTTP 401: проверьте токен; он передаётся без слова Bearer.
- При сетевой ошибке, 429 или ошибке сервера заявка сохраняется, попытки повторяются с паузой до минуты. После нескольких неудач клиент получает уведомление о задержке и телефон техцентра.
- При отказе 400/403/404 клиент получает сообщение, что передать заявку не удалось, и телефон для связи. Ошибка также записывается в журнал. После исправления настроек клиенту нужно отправить новую заявку; отклонённая заявка не пересылается автоматически.
- Максимальный срок повторных попыток — сутки. Затем заявка не отправляется и клиенту ставится в очередь сообщение о неудаче. Если сам MAX недоступен, это сообщение тоже может не доставиться.

Доставка не гарантирует «ровно один раз»: при потере ответа API после фактической отправки сообщение может повториться. В рабочем чате у заявки есть стабильный номер, позволяющий распознать такой повтор. Подтверждение передачи означает успешный ответ API, а не прочтение сотрудником.

## Хранение

Состояние формы, входящие события и очередь исходящих сообщений сохраняются в SQLite в `/data/bot.sqlite3`. Перезапуск сохраняет форму и очередь. Старая база версии 1.0.0 обновляется автоматически добавлением таблиц.

Незавершённые формы и исходящие сообщения хранятся не дольше суток работы приложения; очистка выполняется обработчиком. Если приложение выключено, очистка произойдёт после запуска. После успешной передачи из очереди удаляется тело с именем и телефоном. Технический номер заявки, ID диалога, ID получателя и статус могут храниться до семи дней и очищаются при обработке новых событий. Это логическое удаление записей, не гарантированное физическое стирание SQLite/носителя. Старые резервные копии могут содержать предыдущие данные.

Заявка остаётся сообщением в рабочей группе MAX, а введённый телефон — в истории личного диалога. Срок хранения и доступ к этим чатам регулируют сотрудники. Бот не удаляет сообщения из MAX автоматически. Тексты, имена и телефоны не выводятся в журнал приложения. В режиме настройки в журнал временно выводится ID рабочей группы.

## Установка с нуля по ссылке

В HA: «Настройки → Приложения» (или «Дополнения») → магазин → ⋮ → «Репозитории».
Добавьте https://github.com/RnzTop/ha-max-privolzhsky и установите «MAX — Техцентр Приволжский». Архитектура — aarch64, в Debian называется arm64. Supervisor собирает образ на Raspberry Pi, файловый менеджер не нужен. Для загрузки базового образа нужен доступ к Docker Hub.

## Постоянная работа и Webhook

MAX разрешает Long Polling для разработки и проверки. Для клиентов используйте Webhook: публичный HTTPS на 443, доверенный сертификат и полная цепочка, маршрут `/max/webhook`. MAX также указывает требование публичного сервера со статичным IP. DNS, сертификат и внешняя маршрутизация в этом репозитории не создаются.

В сетевых настройках приложения назначьте свободный порт хоста для `8080/tcp`, например 8099. HTTPS reverse proxy должен передавать только `/max/webhook` на `http://IP_PI:8099/max/webhook` и сохранять заголовок `X-Max-Bot-Api-Secret`. Не публикуйте интерфейс HA или внутренний HTTP-порт напрямую в интернет. Адрес с портом 8123, HA ingress, HTTP и самоподписанный сертификат не подходят.

Пример location для уже настроенного Nginx HTTPS virtual host (подставьте IP Pi):

```nginx
location = /max/webhook {
    client_max_body_size 256k;
    proxy_pass http://192.168.1.50:8099/max/webhook;
    proxy_set_header X-Max-Bot-Api-Secret $http_x_max_bot_api_secret;
    proxy_connect_timeout 5s;
    proxy_read_timeout 25s;
}
```

Заполните `mode: webhook`, `webhook_url` и отдельный случайный `webhook_secret`; сохраните и перезапустите. Приложение обновит подписку на события, включая `bot_added`. Другую подписку по иному URL не удаляет и останавливает запуск, чтобы избежать двойных ответов. Polling не запускается при существующей Webhook-подписке. Подписка не удаляется при остановке приложения.

После обновления и смены режима проверьте реальную заявку в личном диалоге, получение в рабочей группе и повторную работу после перезапуска HA. Для возврата к polling нужно отдельно убрать Webhook-подписку в своей интеграции MAX.
