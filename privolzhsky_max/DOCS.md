# MAX — техцентр «Приволжский», версия 1.0.0

Готово локальное приложение (дополнение/add-on) для Home Assistant Supervisor, Raspberry Pi 4, aarch64. Это приложение из раздела локальных приложений магазина HA: установкой, запуском и журналом управляет Supervisor. Отдельный контейнер вручную запускать не нужно. GitHub, платный конструктор и ИИ не требуются.

## Что делает бот

Приветствие и четыре кнопки: «Записаться на ремонт», «Услуги и цены», «Частые вопросы», «Контакты». Из вложенных разделов можно вернуться в главное меню. В FAQ отдельные ответы о гарантии, зоне ожидания и обслуживании организаций. На неизвестное сообщение — меню и телефон. Работает только в личных диалогах; групповые чаты и каналы намеренно игнорируются.

Запись — переход на https://xn--b1albmndh.xn--p1ai/ (привоил.рф), затем кнопка «Записаться онлайн» и существующая форма АвтоДилер Онлайн. Бот не собирает контакты, не подтверждает время и не синхронизирует календарь. Ссылка мини-приложения MAX для этой версии не нужна.

Данные сайта проверены 7 ноября 2026 года: Базовый проезд, 3, Нижний Новгород; +7 (831) 414-66-99; пн–чт 09:00–18:00, пт 09:00–17:00, выходные сб/вс. ТО от 3 000 ₽, диагностика от 1 900 ₽, подвеска от 500 ₽, двигатель от 5 000 ₽. Итог согласовывается до работ. Гарантия на работы до года — условия уточняются у сотрудника. Подключение виджета подтверждено чтением HTML; отправка заявки не проверялась.

## 1. Установка из магазина по ссылке

1. Откройте «Настройки → Приложения» (в старых версиях «Дополнения») → магазин → ⋮ → «Репозитории».
2. Добавьте https://github.com/RnzTop/ha-max-privolzhsky и обновите страницу магазина.
3. Найдите «MAX — Техцентр Приволжский» и нажмите «Установить». Файловый менеджер не требуется.
4. Supervisor соберёт образ aarch64 на Raspberry Pi. Для первой сборки нужен доступ к Docker Hub. После установки откройте конфигурацию приложения.

Точная версия вашего HA неизвестна, совместимость с конкретным Supervisor ещё не проверена.

## 2. Первый запуск без публичного адреса — только проверка

На вкладке «Конфигурация» приложения заполните поля:

| Поле | Значение |
|---|---|
| `access_token` | Ваш токен из кабинета MAX, вводится только здесь |
| `mode` | `polling` |
| `webhook_url` | Пусто |
| `webhook_secret` | Пусто |

Сохраните, включите «Запуск при загрузке» и нажмите «Запустить». Токен не нужно отправлять в чат или вставлять в исходники. В журнале должно появиться `Бот запущен: polling` после успешной проверки токена. Ошибка HTTP 401 означает, что токен нужно проверить или заменить. Не публикуйте резервные копии HA: они могут содержать настройки с токеном.

В личном диалоге MAX нажмите «Начать» или отправьте `/start`. Проверьте четыре кнопки, FAQ, возврат, карту и переход на сайт. При первом подключении polling MAX возвращает последнее событие, а не всю старую переписку; отправьте новую команду. Если журнал сообщает о существующей Webhook-подписке, этот экземпляр не будет её удалять. Нельзя запускать два экземпляра с одним токеном или совмещать polling с Webhook. Остановите старую интеграцию и отдельно решите, что делать с её подпиской.

**Long Polling разрешён документацией MAX для разработки и тестирования. Постоянную работу с клиентами запускайте после настройки Webhook.**

## 3. Постоянная работа — Webhook

Нужен публичный домен для бота, доступный снаружи HTTPS **на порту 443**, с действительным сертификатом доверенного центра, полной цепочкой и маршрутом `/max/webhook`. MAX также указывает требование публичного сервера со статичным IP. Ни публичный адрес Raspberry Pi, ни домен в этой задаче не предоставлены, поэтому внешняя маршрутизация здесь не настроена.

1. Настройте отдельный домен/поддомен для бота и HTTPS reverse proxy, который передаёт только `POST /max/webhook` на Raspberry Pi. Можно использовать уже имеющийся reverse proxy или соответствующее приложение HA. Изменять сайт техцентра не нужно. Внешний HTTP или самоподписанный сертификат MAX не принимает. Адрес интерфейса HA с `:8123` и HA ingress для этого не подходят.
2. В сетевых настройках дополнения назначьте свободный порт хоста для `8080/tcp`, например `8099`. Reverse proxy направляет запросы на `http://IP_RASPBERRY_PI:8099/max/webhook`. Не направляйте публичный трафик на весь интерфейс HA и не пробрасывайте 8099 напрямую в интернет. Сохраните заголовок `X-Max-Bot-Api-Secret` без изменений. Порт по умолчанию отключён, polling его не использует.
3. На стороне reverse proxy ограничьте размер тела 256 КБ и время запроса до 30 секунд. Пример фрагмента для **существующего** Nginx HTTPS virtual host (подставьте IP Pi):

```nginx
location = /max/webhook {
    client_max_body_size 256k;
    proxy_pass http://192.168.1.50:8099/max/webhook;
    proxy_set_header X-Max-Bot-Api-Secret $http_x_max_bot_api_secret;
    proxy_connect_timeout 5s;
    proxy_read_timeout 25s;
}
```

Этот фрагмент не создаёт DNS, сертификат и HTTPS virtual host: их нужно настроить в выбранном reverse proxy. Публичный `/health` не требуется. Не добавляйте авторизацию браузера/страницу входа перед Webhook.

4. Придумайте случайный `webhook_secret` из 32–64 латинских букв и цифр (также допустимы `_` и `-`). Это отдельный секрет, не токен бота. Укажите `mode: webhook`, `webhook_url: https://ВАШ-ДОМЕН/max/webhook` и этот секрет. Сохраните и перезапустите дополнение.
5. Дополнение сначала поднимет HTTP-приёмник, проверит токен, затем зарегистрирует подписку на `bot_started`, `message_created`, `message_callback`. Существующую подписку с тем же URL обновит, чужую по другому URL не тронет и остановит запуск, чтобы не создать двойные ответы. Подписка при остановке дополнения автоматически не удаляется.
6. После строки `Бот запущен: webhook` повторите ручную проверку в MAX. Успешная регистрация сама по себе ещё не доказывает доступность адреса с серверов MAX. Проверьте реальную доставку новым `/start`, нажатиями кнопок и после перезапуска HA.

Если Webhook не отвечает, MAX повторяет доставку, а после длительной недоступности может удалить подписку. После восстановления адреса перезапустите приложение для повторной регистрации. Для возврата к polling сначала отдельно удалите существующую подписку в своей интеграции MAX; одно переключение режима её не удаляет.

## Журнал, хранение и обслуживание

Журнал — вкладка «Журнал» этого приложения в HA. В нём фиксируются запуск, режим, обработка ответа и числовые ошибки HTTP; тексты сообщений, телефон клиента, идентификаторы чатов и токен не выводятся. Время стандартного журнала Python — время контейнера (обычно UTC), интерфейс HA может показывать локальное время.

Очередь событий и marker polling хранятся в `/data/bot.sqlite3`, сохраняются при перезапуске и входят в резервную копию дополнения. Входящий Webhook подтверждается HTTP 200 после сохранения на диск. Обработанное тело удаляется из очереди; хеш для подавления повторов хранится до 7 дней и удаляется при следующем приёме событий. Необработанные события сохраняются до обработки/удаления дополнения: они могут содержать присланные пользователем сведения, хотя бот их не запрашивает. На сетевых сбоях ответы повторяются с паузой; ошибки 400/403/404 пропускаются с записью в журнал, чтобы очередь не зависла. При 401 требуется проверить токен.

Доставка не имеет гарантии «ровно один раз»: редкий повтор ответа возможен, если MAX принял ответ, а соединение оборвалось до подтверждения либо питание пропало до фиксации результата на диске. После сбоя проверьте журнал. Удаление дополнения удалит его локальные данные; перед изменениями используйте резервную копию HA. Обновление: замените исходники, увеличьте `version` в `config.yaml`, обновите магазин и приложение.

## Образ aarch64 и проверяемость

`privolzhsky-max-aarch64-1.0.0.docker.tar.gz` — готовый архив образа Linux/arm64, тег `local/aarch64-addon-privolzhsky_max:1.0.0`. Образ собран из официальных слоёв Python и дополнительного слоя приложения без исполнения ARM-бинарников; SHA256 всех слоёв и соответствие кода проверены. Базовый digest указан в `IMAGE-INFO.json`. Docker runtime на рабочем компьютере отсутствует, запуск контейнера здесь не проверялся.

Основной путь установки выше — штатная локальная сборка Supervisor. Архив образа предоставлен дополнительно для переноса/проверки специалистом, загрузка через `docker load -i privolzhsky-max-aarch64-1.0.0.docker.tar.gz` выполняется **на Debian-хосте с тем Docker, которым пользуется Supervisor**, а не в браузере HA. Это не отдельный способ запуска бота: не используйте `docker run`. Предварительная загрузка не гарантирует, что конкретная версия Supervisor пропустит свою сборку. Сама карточка дополнения создаётся только копированием исходной папки и обновлением магазина.

В `CHECKS.md` приведены результаты проверок, в `SHA256SUMS` — контрольные суммы файлов поставки. Тесты из исходников: `python3 -m unittest discover -s tests -v` в папке приложения; они используют искусственные события, локальный HTTP и временную базу. Настоящий токен не нужен.
